# CueFleet 实时行情与策略特征

为信号服务设计行情输入、迁移已有策略或核对训练与运行时的特征时使用本页。历史研究继续使用 `scripts/market_data.py` 下载和切片。

## 当前能力

客户端已有图表行情、历史 K 线缓存和 BTC／ETH 指数报价订阅。这些组件目前供客户端内部使用。已发布的本机交易 API 中，`GET /v1/accounts/{accountId}/market` 返回账号支付率与交易限额。开发环境的「AI 交易」通过信号服务请求提供下面的收盘 K 线窗口。

离线开发可以用同一行情口径的历史 K 线构造预测请求，验证特征与模型输出。实时输入尚未接通时，报告如实标明状态，避免在每个策略进程内默认启动独立的币安行情采集器。

## 行情共享 v1

客户端为每种行情源和标的维护共享采集与缓存。行情频道按需合并订阅，多个策略使用同一频道；相同历史区间的并发预热和缺口补齐合并成一次上游请求。常规更新走公共 WebSocket，历史预热和补缺使用 REST。由客户端统一重连和退避；遇到限流遵守上游重试信号。策略进程无需币安密钥。 [币安 USDⓈ-M 接口与限流说明](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/general-info)

信号服务在连接时声明所需的行情源、标的、K 线粒度和最少收盘根数。比如 `ETHUSDT`、`perpetual`、`1m`、最近 120 根。CueFleet 满足连续预热窗口后，在调用信号服务的 `POST /v1/predict` 时附上该窗口。多个策略即使使用不同权重、指标或语言，都可从同一批 K 线各自计算特征。K 线粒度和事件合约到期周期分别配置，例如用 `1m` K 线预测 `10m` 到期合约。

CF 只提供有限的实时历史窗口。上限按每个行情源、标的和粒度分别计算，每路最多 600 根已收盘 K 线。接入时以客户端公布的实际能力和上限为准。模型声明的预热长度超过上限时，由用户提前下载或导入长历史，再用 CF 的窗口接续。拼接必须使用同一行情源、标的和粒度，以开盘时间去重，并确认最近的预热窗口连续。两段重叠处使用最新确认的已收盘数据。历史仍不足时明确报告缺少根数，并等待补齐或由用户缩短策略窗口。策略进程无需为此自动轮询币安。

预测请求使用下列数据形状。价格和成交量用十进制字符串，时间是 UTC Unix 毫秒。`closeTime` 指右开区间终点，即下一根的开盘边界。`asOf` 是客户端交给策略的行情观测时间。

```json
{
  "version": "cuefleet.signal.v1",
  "requestId": "00000000-0000-4000-8000-000000000001",
  "symbol": "ETHUSDT",
  "period": "10m",
  "market": {
    "source": "binance-usdm-perpetual",
    "interval": "1m",
    "asOf": 1760000100100,
    "candles": [
      {
        "openTime": 1760000040000,
        "closeTime": 1760000100000,
        "open": "2410.10",
        "high": "2412.50",
        "low": "2409.90",
        "close": "2411.80",
        "volume": "782.65"
      }
    ]
  }
}
```

示例只展示一根。真实请求必须先满足模型声明的预热长度。信号服务返回版本、相同的 `requestId`、`decision`，并将 `market.asOf` 原样作为 `observedAt` 返回。模型进程只处理行情和信号，账号、金额、模式和交易凭据由 CueFleet 管理。

## 特征一致性与验收

- 默认只用已收盘 K 线计算特征。按行情源、标的、粒度和开盘时间去重，按时间升序取连续窗口。训练与推理复用同一份特征顺序、滚动窗口、缺失值规则和训练阶段保存的归一化参数。
- 永续成交 K 线（`binance-usdm-perpetual`）可用于计算成交量特征。指数 K 线（`binance-usdm-index`）的成交量字段为 `null`。v1 每个标的声明一个行情窗口，需要成交量的策略使用永续成交行情。保留行情来源，避免把实时指数点拼作永续成交 K 线。 [币安 USDⓈ-M 行情接口](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)
- 断线、有缺口、过期或未完成预热时，暂停发起该策略的预测。客户端补齐后恢复。测试相同数据同时喂给离线与实时入口，检查特征值与方向一致。再用多个策略订阅同源窗口，验证上游不会随策略数量重复连接，且掉线补缺只产生一次上游请求。
